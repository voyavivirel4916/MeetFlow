# MeetFlow 分阶段开发与本地 Agent 提示词

## 1. 使用原则

不要一次性要求 Agent “完成整个项目”。应按阶段开发，每个阶段结束后：

1. 查看修改文件；
2. 实际运行后端和前端；
3. 运行测试；
4. 按验收标准人工操作；
5. 修复问题并提交 Git；
6. 再进入下一阶段。

每次提示 Agent 时，同时向它提供或要求它先阅读：

- `Docs/03-需求边界与MVP.md`；
- `Docs/05-本地Agent技术实施文档.md`；
- `Docs/06-数据库API与页面设计.md`；
- `Docs/07-验收标准与测试计划.md`。

## 2. 阶段 0：工程脚手架

### 目标

- 创建前后端目录；
- 配置代码格式、环境变量和数据库连接；
- 建立最小健康检查；
- 配置基础测试；
- 编写本地启动说明。

### 可复制提示词

```text
请先阅读 Docs/03、05、06、07 号文档，然后只完成 MeetFlow 的“阶段0：工程脚手架”。

要求：
1. 使用既定的 Vue 3 + TypeScript + Vite 前端和 FastAPI + SQLAlchemy 后端；
2. 建立文档规定的目录结构；
3. 配置 SQLite、Alembic、.env.example、CORS 和统一错误响应基础；
4. 后端提供 /api/v1/health，前端提供最小可访问页面；
5. 配置 Pytest 和 Vitest，分别添加一个能实际运行的示例测试；
6. 更新 Src/README.md，写明安装、迁移、启动和测试命令；
7. 不要提前实现用户、小组或排期业务。

完成后请实际运行测试，并报告修改文件、测试命令与结果、遗留问题。不得声称未运行的测试已通过。
```

## 3. 阶段 1：账户与小组

### 目标

- 注册、登录、当前用户；
- 创建小组、邀请码加入；
- 成员列表和基础权限；
- 对应页面与测试。

### 可复制提示词

```text
请在现有 MeetFlow 仓库中完成“阶段1：账户与小组”，不要实现排期。

先检查当前代码和测试，再严格依据 Docs/03、05、06、07：
1. 实现 users、groups、group_members 数据模型和数据库迁移；
2. 实现注册、登录、当前用户、创建小组、邀请码加入和成员列表接口；
3. 密码必须安全哈希，后端必须验证小组权限；
4. 实现登录/注册、我的小组、创建/加入小组、小组详情基础页面；
5. 补充重复用户名、无效邀请码、重复加入和未授权访问测试；
6. 提供演示数据或清晰的手工测试步骤；
7. 更新相关 API 和启动文档。

完成后运行数据库迁移、后端测试和前端测试，并报告结果。不要实现文档范围外功能。
```

## 4. 阶段 2：排期与空闲状态

### 目标

- 排期和候选时间段；
- 参与者与必到成员；
- 排期状态机；
- 成员三态填写；
- 时间矩阵。

### 可复制提示词

```text
请完成 MeetFlow“阶段2：排期与空闲状态”。

要求：
1. 实现 scheduling_polls、poll_participants、poll_time_slots、availability_votes 及迁移；
2. 实现草稿、开启、截止、取消状态转换，并拒绝非法转换；
3. 实现候选时间段校验、参与者重要程度和当前用户批量保存空闲状态；
4. 同一用户对同一时间段只能保留一条状态；
5. 实现排期编辑、成员填写和时间矩阵页面；
6. 处理加载、空数据、错误、截止后提交和无权限状态；
7. 为状态机、时间校验、重复提交和数据隔离添加测试。

本阶段不实现推荐算法、会议和任务。完成后实际运行全部相关测试并报告结果。
```

## 5. 阶段 3：推荐算法与可视化

### 目标

- 确定性排期评分；
- 稳定排序和解释；
- 热力图、排名和冲突列表；
- 推荐算法单元测试。

### 可复制提示词

```text
请完成 MeetFlow“阶段3：推荐算法与可视化”。

严格按照 Docs/05 和 Docs/06 的权重、公式和排序规则：
1. 将算法实现为独立、无网络依赖、可单元测试的纯逻辑模块；
2. 返回必到成员冲突数、有空/勉强/没空/未提交人数、得分、排名和推荐理由；
3. 实现 recommendations 和 matrix 接口；
4. 实现时间热力图、成员矩阵、排名卡片和冲突成员列表；
5. 同一输入必须得到相同结果；
6. 覆盖所有成员有空、关键成员冲突、同分、未提交、全部有冲突等测试场景；
7. 不加入机器学习、大模型或第三方排期服务。

完成后运行算法单元测试、接口测试和前端测试，并展示一个可复现的演示数据结果。
```

## 6. 阶段 4：会议与任务闭环

### 目标

- 确认候选时间并生成会议；
- 会议议程与纪要；
- 创建和指派任务；
- 任务看板与个人待办。

### 可复制提示词

```text
请完成 MeetFlow“阶段4：会议与任务闭环”。

要求：
1. 实现 meetings、tasks 数据模型和迁移；
2. 只有有权限者可以从所属排期的有效候选时间确认会议；
3. 重复确认请求不能生成重复会议；
4. 实现会议详情、议程、纪要和结束会议；
5. 实现任务创建、指派、截止时间、状态更新、小组看板和个人待办；
6. 后端实施权限校验，不能只在前端隐藏按钮；
7. 添加会议确认幂等性、纪要权限、任务数据隔离和状态更新测试；
8. 保证阶段1至3功能和测试不回退。

完成后运行完整主流程，并报告测试结果和遗留问题。
```

## 7. 阶段 5：完善、测试与发布准备

### 目标

- 工作台和统计；
- 完整错误状态；
- 测试报告证据；
- 演示数据；
- 发布和用户反馈准备。

### 可复制提示词

```text
请完成 MeetFlow“阶段5：完善、测试与发布准备”，不得增加新的大型业务模块。

要求：
1. 实现个人工作台和小组基础统计；
2. 检查所有页面的加载、空数据、错误和无权限状态；
3. 创建稳定、可重复执行的演示数据脚本；
4. 完善后端单元测试、接口测试和关键前端测试；
5. 按 Docs/07 执行端到端主流程并记录结果；
6. 检查密码、权限、输入校验、跨组数据隔离和配置文件；
7. 完善 README，包括安装、迁移、启动、测试、演示账号和发布说明；
8. 删除调试代码和无用依赖；
9. 输出可用于课程测试报告的用例结果和截图清单。

完成后实际运行完整测试套件，报告测试命令、通过/失败数量、已知问题和发布前检查项。
```

## 8. Agent 每阶段统一收尾提示词

```text
请对本阶段进行收尾检查：
1. 对照需求编号和验收标准确认遗漏项；
2. 运行格式检查、后端测试、前端测试和构建；
3. 列出全部修改文件及作用；
4. 列出实际执行的命令和结果；
5. 列出已知问题、风险和未完成项；
6. 更新受影响的文档；
7. 给出建议的 Git 提交信息，但不要声称未执行的操作已完成。
```

## 9. 推荐 Git 分支与提交

建议分支：

```text
main
├── feature/auth-groups
├── feature/scheduling
├── feature/recommendation
├── feature/meetings-tasks
└── test/release-check
```

建议提交信息示例：

```text
docs: 完成立项会议与NABCD文档
feat(auth): 实现注册登录和身份认证
feat(groups): 实现邀请码加入小组
feat(polls): 实现排期与三态时间填写
feat(recommendation): 实现可解释排期排序
feat(meetings): 实现会议确认与纪要
feat(tasks): 实现任务看板与个人待办
test: 补充权限和排期算法测试
docs: 更新部署与用户使用说明
```
