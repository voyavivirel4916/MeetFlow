# T34 本地安装与独立演示

首版仅本机使用，`http://127.0.0.1:8000/`发给别人不能访问你的电脑，公开部署属于后续课程交付。

## 安装与运行

使用Python 3.11、Node 22.20，按锁文件安装，在PowerShell运行：

```powershell
cd D:\软件工程\Src\frontend
npm ci
npm run build
cd ..\backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --require-hashes -r requirements-dev.txt
.\.venv\Scripts\python.exe -m app.db.migrate
.\.venv\Scripts\python.exe -m app
```

已有`.venv`跳过创建。仅运行可安装`requirements.txt`，测试需要开发依赖。已有库升级前停服备份，当前版本0005；前端改后构建、后端改后重启。只启动后端即可同时访问页面与接口。

本轮新虚拟环境已离线安装锁定运行依赖，通过`pip check`、新库迁移、演示和HTTP启动，见[记录](evidence/t34-install.json)。这验证本机新环境，不代表所有操作系统。前端新目录结果见[记录](evidence/t34-frontend-install.json)。

## 四账号独立演示

正常库不自动生成账号。演示使用尚不存在的独立目录：

```powershell
cd D:\软件工程\Src\backend
.\.venv\Scripts\python.exe -m app.demo --data-dir D:\软件工程\Src\backend\data\demo-four
$env:MEETFLOW_DATA_DIR='D:\软件工程\Src\backend\data\demo-four'
$env:MEETFLOW_PORT='8001'
.\.venv\Scripts\python.exe -m app
```

打开`http://127.0.0.1:8001/`。账号为`demo_owner`、`demo_member1`、`demo_member2`、`demo_member3`；仅演示密码均为`MeetFlowDemo2026!`。使用四个独立浏览器会话或配置，同一浏览器的普通标签页会共享登录。

数据包含未填写的开放排期，以及带纪要和两项任务的已确认会议。生成器拒绝正常数据目录和任何已有目标目录，不覆盖或清空数据。日期过期后换新目录生成。

Ctrl+C停止演示服务，回到正常库前清除当前终端设置：

```powershell
Remove-Item Env:MEETFLOW_DATA_DIR -ErrorAction SilentlyContinue
Remove-Item Env:MEETFLOW_PORT -ErrorAction SilentlyContinue
```

## 备份与恢复

先停服，再复制`Src/backend/data/meetflow.sqlite3`到独立目录并注明时间。恢复前另存当前文件，再复制选定备份回配置目录，核对结构与外键，启动后检查登录、矩阵、会议和任务。恢复库应撤销旧会话并重新登录。不要在服务写入时覆盖数据库。

自动恢复工具只操作临时副本，不是实际数据的备份命令；使用者仍需妥善保存真实备份。
