# T17 本人全量投票接口

日期：2026-10-27。对应MF-06、MF-13、API-06、AC-05及TV-05。本项完成真实接口与数据库约束；填写页面留到T18，不代表投票页面、矩阵、推荐或产品验收已经完成。

## 使用规则

接口前缀 `/api/v1`，使用当前登录会话，只允许本组且属于本次排期的参与者操作本人答案。负责人也不能代填，未列入参与者的负责人同样不能填写。

| 请求 | 正文与结果 |
| --- | --- |
| GET /polls/{poll_id}/votes/me | 返回 `{poll_id, submitted_at, votes:[{slot_id, availability}]}`；未提交为 `submitted_at:null, votes:[]`；截止、取消或确认后仍可回看 |
| PUT /polls/{poll_id}/votes/me | 正文 `{votes:[{slot_id, availability}]}`，必须恰好包含该排期全部候选；成功返回与GET相同结构 |

`availability`仅接受`AVAILABLE`（有空）、`MAYBE`（勉强）、`UNAVAILABLE`（没空）。不存在可提交的“未知”值；未提交状态用空答案表示。请求不接受`user_id`、提交时间或其他额外字段。

漏填、重复、跨排期时段、非法值或代填字段返回422；组内非参与者403，组外或不存在的排期404，未登录401。只有OPEN且未截止可写；已关闭/到期返回409 `POLL_CLOSED`，其他状态409 `STATE_CONFLICT`。响应不缓存，提交时间使用服务端UTC毫秒时间，与既有接口一致。

## 保存与迁移

- 新增`0003_votes`迁移；每个时段、每位参与者只有一格答案，复合外键同时约束时段归属和参与者归属。数据库直接写入也不能跨排期、填未知值或留下重复格。
- 写事务先取得SQLite写锁，再核对权限、状态和截止；与关闭、取消使用同一事务策略。等待锁时跨过截止同样拒绝。
- 一次替换本人全部答案并更新参与者的`submitted_at`；任一步骤或提交失败，都回滚旧答案和时间。并发提交按最后成功提交覆盖，不混合两份答案，不影响其他参与者。
- GET在同一只读快照中读取答案和提交时间，不偷偷关闭排期。授权的到期写请求会先落库CLOSED，再拒绝修改答案；越权请求无此副作用。
- 网络响应丢失时可GET核对，再由用户决定是否重新提交；接口不自动重试。数据库繁忙503 `DB_BUSY`，存储故障503 `STORAGE_UNAVAILABLE`，唯一性/关联约束冲突409。

已有库先备份，再在`Src/backend`执行`.venv/Scripts/python.exe -m app.db.migrate`，然后重启服务。此次开发库已保留升级前备份，升级后逐表核对原记录一致，新增投票表为空；未写入演示账号或答案。备份与本地数据均不入库。
