# MeetFlow T05 后端基础工程记录

版本：B0.1｜2026-10-26。对应T05与NFR-08，依照[开发约定](05-本地Agent技术实施文档.md)和[系统设计](12-系统设计文档.md)。启动操作集中在[后端README](../Src/backend/README.md)，本文件只记录范围和验证结果。

## 1. 本轮形成的基础能力

- 独立Python环境及运行/开发依赖锁文件，固定版本并核对下载哈希。开发清单受运行锁文件约束，产品环境不依赖系统已装的软件包。
- 应用工厂、启动入口和配置读取。默认本机127.0.0.1、单进程；`.env`读取位置和相对数据目录不随终端位置变化，支持合法环境变量覆盖。
- 启动配置与目录可写检查；检查文件自动清理，失败终止启动，不创建数据库或清空已有文件。
- 成功响应、统一错误、服务端request_id与安全请求日志。参数验证错误不回显输入值，未知故障不返回堆栈或异常原文，拒绝非本机Host。
- `/livez`启动探针及本机`/openapi.json`。探针只表达进程启动，正式`/api/v1/health`及数据库结构校验随T07/T08接入。

框架的基本输入模型拒绝未知字段；这不表示后续业务字段、权限、来源校验、正文大小、会话和事务已完成。前端路由/API客户端、迁移、认证等分别仍由T06、T07、T09及后续任务交付。

## 3. 验证记录

验证包括配置默认值/覆盖、非法配置失败、本机绑定限制、不可写目录、已有文件不变、应用工厂隔离、探针与未实现接口区分、请求关联ID、404/405/422/500响应、字段值与异常原文不进入日志/响应。测试使用临时数据目录，未运行业务验收。

实际启动检查采用本机真实Uvicorn进程，读取`/livez`与`/openapi.json`，并核对未实现的`/api/v1/health`保持404。依赖一致性另用`pip check`验证。最终通过数量及提交可由测试输出与Git历史追踪，不预填数据库、性能或真实用户结果。

本轮实际结果：后端23项Pytest通过；仓库/文档/锁文件32项检查通过；`pip check`无依赖冲突；真实HTTP下`/livez`为200且响应体与响应头request_id一致，OpenAPI仅列启动探针，正式健康接口为404。T04示例另在Chrome、Edge通过交互与配色检查，记录在16号规范。启动后只创建可写数据目录，没有生成业务库。
