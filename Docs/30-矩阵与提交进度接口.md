# T19 矩阵与提交进度接口

日期：2026-10-27。对应MF-07、API-07（矩阵部分）、AC-06及TV-06。完成接口与统计，矩阵页面留T20，推荐接口留后续任务；无数据库迁移或新依赖。

## 接口与统计

`GET /api/v1/polls/{poll_id}/matrix`，沿用登录Cookie和统一响应。小组成员都可读，包括未被列为本次参与者的组员；组外/不存在404，未登录401。草稿、收集中、关闭、确认及取消状态均可查看矩阵；这些规则不代表所有状态都可填写或生成推荐。

| 字段 | 含义 |
| --- | --- |
| poll_id、effective_status | 当前排期及有效状态；OPEN到截止时按服务端时间返回CLOSED |
| participants | 参与者的user_id、username、importance、submitted_at及该人的四类计数 |
| slots | 候选id、start_at、end_at及该时段的四类计数 |
| cells | 全部参与者×候选时段，每格含user_id、slot_id、availability；未填明确为null |
| progress | participant_count总人数、submitted_count已提交人数、unsubmitted_count未提交人数 |

四类计数为`available_count`、`maybe_count`、`unavailable_count`、`unanswered_count`。逐人计数之和等于候选数，逐时段计数之和等于参与者数；未知不会算作有空或没空。提交人数按参与者已保存的`submitted_at`计算，一人覆盖答案不会增加提交人数。本页尚未保存的选择不进入统计。

参与者按user_id排序；时段按开始、结束、id排序，单元格按参与者顺序逐个展开时段。空草稿允许空矩阵，计数为0。只返回本排期的公开信息，不返回邮箱、密码或会话资料，时间沿用UTC毫秒格式。

## 一致性与验证

成员、候选、答案及提交时间在同一SQLite只读快照中读取，避免投票提交中途读到旧提交时间和新答案的混合结果；答案一次批量查询，不逐格访问数据库。读取完成后判断有效截止状态，GET不写库、不偷偷关闭排期，响应`Cache-Control: no-store`。

新增19项专项测试覆盖四人三时段、三态与未知、覆盖提交、20×15共300格及固定查询次数、跨排期隔离、全部状态、权限、截止、只读无副作用、并发提交期间快照一致性。Chrome、Edge真实会话检查矩阵、进度、关闭后回看及权限，并回归小组页面；Chrome同时回归T18填写页面。
