# MeetFlow 第一版需求边界

整理基线：B1｜2026-10-25。本页是开发范围速查，完整需求、规则与验收定义沿用[需求分析文档 V1.2](09-需求分析文档.md)。保留 MF、NFR、AC 编号，不再维护旧 FR 编号的第二套现行定义。

## 1. 第一版目标

让四个测试账号完成“小组—排期—推荐—会议—纪要—任务”的全过程，支持在会议后持续查看和更新任务。四个账号是测试参与者，不代表四名开发成员。

实现基线为本地单实例、桌面 Chrome/Edge、SQLite；每组最多20人，每次1～15个候选时段。课程公开发布另列后续交付阶段，不等同于本地第一版完成。

## 3. 必须一致的业务规则

- **角色**：小组仅有负责人 OWNER 和普通成员 MEMBER。由 owner_id确定负责人；不设小组管理员、系统管理后台或独立会议记录人。负责人编辑纪要、创建和指派任务；负责人及任务执行人可更新任务状态。
- **冻结**：DRAFT阶段可以修改候选时间和参与者；发布后两者冻结。第一版不提供重新开启或事后改期。
- **时间**：填写截止必须早于所有候选开始时间。以服务端时钟为准，达到截止时刻就拒绝新提交。
- **填写**：有空、勉强、没空为三个可提交值；未提交显示未知。全量保存失败时不产生部分更新，不接受代填。
- **排序**：必到没空人数升序 → 最终分降序 → 有空人数降序 → 开始时间升序 → 结束时间升序 → 候选ID升序。权重和复算示例只在[需求基线第5节](09-需求分析文档.md)维护。
- **解释**：必到未填单独提示，不能解释为全部可参加；必到勉强显示风险。全时段有冲突时照实展示，不自动确认。
- **确认**：只有CLOSED可首次确认。存在必到没空、必到未填或选择非第一名时，要求确认警告并填写理由。重复确认同一时段返回原会议，另一时段返回冲突。
- **任务**：纯文本、列表、组内执行人和截止时间；TODO、IN_PROGRESS、DONE三态。完成后可以重新置为待办，清空完成时间。第一版不编辑任务基本信息、不删除历史任务；状态更新用于持续跟踪。
- **一致性**：同一时段每人最多一份答案，每个排期最多一场会议；个人待办与组任务读取同一份数据。

## 4. 第一版边界

不包含统计图、图片导出、站内或第三方推送、拖拽看板、附件、富文本、任务评论/子任务、自动纪要、私人日历、教务系统、实时聊天、成员退出/转让、额外角色和历史业务物理删除。

本版不承诺手机适配、公网访问、跨设备访问、自动备份或PostgreSQL部署。桌面使用文字与颜色共同表达状态；按需手动刷新。后续扩展通过[变更记录](13-版本与变更记录.md)进入需求，不在开发中隐式加入。

## 5. 非功能与完成条件

沿用NFR-01～NFR-08：20人×15时段、200任务的列表与推荐性能目标；入组填写易用性；桌面兼容；安全隔离；事务与恢复；推荐可解释；北京时间显示和截止边界；可维护与本地部署。具体阈值和测量方法见[需求基线第7节](09-需求分析文档.md)，尚无实测结果。

第一版完成须满足全部P0及NFR验收，有可重复启动方式、独立测试数据、四账号演示和测试证据。当前完成的是文档整理，业务实现与验收仍待进行。课程原型、UML、甘特图、测试报告、用户说明、公开发布和真实反馈另按[开发计划](08-分阶段开发与Agent提示词.md)逐项交付。
