# MeetFlow 第一版验收与测试计划

整理基线：B1｜2026-10-25。验收编号沿用[需求基线V1.2](09-需求分析文档.md)，实现层验证沿用[系统设计](12-系统设计文档.md)的TV编号。本文不预填实际通过结果。

## 1. 主流程

E2E-01：四个独立账号在本机浏览器会话中完成：A建组 → B/C/D加入 → A创建三个时段并指定必到者 → 四人填写 → 核对矩阵和排名 → A关闭收集并确认 → A记录纪要并创建两项任务 → 执行人更新 → 核对小组列表与个人待办。

四个测试账号由两位开发成员操作即可。数据使用专用演示小组，不代替后续真实用户反馈。P1首页不属于这条必过流程。

## 3. 测试分层

- 单元：排序、分数、解释、状态转换、截止边界。算法直接使用09号第5节的T1/T2/T3样本，并测试同起止时间、输入乱序和必到未填。
- 集成：会话、权限、对象归属、完整事务、唯一约束；并发确认使用两个独立连接，验证重复请求返回结果及数据条数。
- 前端组件：三态选择、全量提交、保存失败保留输入、错误显示、推荐解释、任务状态操作。
- 人工：Chrome/Edge、1280×720及以上视口、键盘操作、加载/空数据/错误状态和完整主流程。

测试数据库与开发数据隔离，故障和恢复测试只操作临时副本。现有Src/scripts文档测试检查内容和引用一致性，不代表上述业务测试已经通过。

## 4. 非功能验证

| 项目 | 第一版目标与方法 |
| --- | --- |
| 性能 | 20名成员×15时段、200条任务，本地单用户顺序请求；预热后各采样30次列表/推荐请求，P95≤1秒且无5xx |
| 易用 | 5名非开发测试者中至少4名，从登录成功起3分钟内完成有效邀请码入组及3时段填写，无操作指导 |
| 时间 | 显示北京时间；拒绝无时区输入；截止前1秒允许、等于及之后拒绝 |
| 可靠性 | 并发确认最多一条会议；成功保存数据重启后仍在；停服复制数据库并进行一次恢复核对 |
| 安全 | 代填、跨组和普通成员管理操作拒绝；纪要按文本展示；日志不含密码或令牌 |
| 运行 | 新环境可按说明启动本机服务；结构版本不符时明确报错；测试不污染演示数据 |

指标均为验收目标。报告须包含设备、依赖版本、数据规模、原始样本、失败情况及复测结果，不能只写“流畅”或“全部正常”。
