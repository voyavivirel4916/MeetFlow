# T12 小组、成员与邀请码接口

日期：2026-10-26。对应MF-02、MF-13、API-02/03及AC-02，沿用本地第一版。复用T07的groups、group_members，无新迁移或依赖。

## 已实现

以下路径均以 `/api/v1` 开头，需要有效Cookie会话，使用统一响应封套并禁止缓存。

| 方法与路径 | 行为 |
| --- | --- |
| POST /groups | 输入`{name,description?}`；创建小组和负责人成员关系，同一事务提交，成功201 |
| GET /groups | 只列本人所在组；默认page=1、page_size=20，上限50；按created_at、id倒序，返回items/page/page_size/total |
| GET /groups/{id} | 本组成员读取详情：id/name/description/owner_id/member_count |
| GET /groups/{id}/members | 返回items，单项仅user_id/username/role；角色从owner_id导出，不返回邮箱或密码信息 |
| POST /groups/join | 输入`{invite_code}`，成功200；重复加入不新增关系，满员时已有成员仍可重复加入 |
| POST /groups/{id}/invite-code/reset | 输入`{}`，仅负责人可操作；返回新invite_code和invite_enabled=true，旧码立即失效，成员关系保留 |

GroupOut仅向负责人附加invite_code、invite_enabled，普通成员的列表、详情及入组响应都不包含这两个字段。非成员访问与小组不存在统一404；组内普通成员重置邀请码返回403。后续模块可复用 `groups/service.py` 的require_member、require_owner，不信任前端传入角色。

名称trim后1～100字符，说明默认空、上限10000字符，保留纯文本；拒绝非法Unicode和空字符。邀请码为随机12位ASCII大写字母/数字，输入trim并转大写，不接受Unicode近似字符。无效格式422，格式有效但不存在或停用的新入组请求404。未知输入字段拒绝，客户端不能指定负责人或邀请码。

## 事务与边界

- 创建时同时写组与负责人关系，任一步或提交失败都回滚，不留下孤立组。
- 加入先取得SQLite写锁，在同一事务中查码、检查已有关系及20人容量，再插入；并发抢最后名额只能一个成功，另一个409。重复加入检查先于停用及容量限制。
- 重置在写事务中重新检查负责人。新码不能等于旧码，邀请码碰撞最多尝试3次；耗尽返回503，旧码及成员保持原样。普通数据库错误不当作随机码碰撞重试。
- 数据库繁忙返回503 DB_BUSY，提交失败返回503 STORAGE_UNAVAILABLE，不返回假成功。写请求仍不自动重试。

## 验证与复现

新增56项小组测试，完整后端225项通过；前端79项、构建和32项仓库检查通过。测试覆盖四账号AC-02、输入长度与分页、组外404/组内403、隐私字段、关闭邀请码、碰撞重试、20/21人竞争、同用户并发重复加入、写锁、成员插入失败与提交回滚。邀请码和组文本不进入请求日志。

Chrome、Edge正式构建及Chrome开发代理通过四会话真实Cookie检查：建组、三人加入、重复加入、成员摘要、权限拒绝、重置后旧码无效、刷新和退出失效。测试使用独立临时库，不导入开发数据。

复现：后端执行 `.venv/Scripts/python.exe -m pytest -q`；前端先构建，再执行 `npm run check:groups`，开发代理用 `node browser.check.mjs --groups`。浏览器环境见[前端说明](../Src/frontend/README.md)。

小组列表、详情、建组入组表单仍由T13接入；本轮不增加退出小组、转让负责人、管理后台或排期接口。
