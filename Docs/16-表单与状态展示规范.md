# MeetFlow T04 表单与状态展示规范

版本：UI1｜2026-10-26。适用于正式前端的T06、T10、T16、T18、T20、T23、T25、T27、T29、T30；以[需求](09-需求分析文档.md)、[系统设计](12-系统设计文档.md)和[原型交接](15-设计图与需求原型核对.md)为边界。

## 1. 使用方式

沿用马若曦确定的“时间拼图”：暖白背景、靛蓝主操作、少量珊瑚橙强调。可在[状态示例页](ui/form-states.html)切换查看加载、空数据、错误、无权限、保存成功、未确认保存及会话过期。示例不连接接口，不代表产品页面已经实现。

参考截图：[就绪](images/t04/01-ready.png)、[错误摘要与字段定位](images/t04/02-error.png)。截图仅包含示例输入。

本规范将原型视觉整理为正式实现约定；T02原型保持P0.3。原型中缺少的字段、2000字限制等简化项继续按15号清单交接，不作为本规范的正式规则。

## 2. 视觉和表单约定

| 项目 | 统一规则 |
| --- | --- |
| 基础颜色 | 背景`#F7F5EF`，正文`#292D50`，次要文字`#69616A`，主操作`#454C96`，强调`#D57660`；浅色强调不用于小字正文 |
| 状态文字/底色 | 有空`#48508F / #E1E4F7`；勉强`#866022 / #FBEFCE`；没空`#954C39 / #F8E2D8`；未知`#69616A / #EFEBE5`，同时显示文字、符号，未知可加斜纹 |
| 字号与目标 | 正文14px起，说明12px起；主要按钮和选项点击区至少40px高；不把关键解释缩成装饰小字 |
| 输入与标签 | 语义form、关联label；必填以文字说明；placeholder只作举例，不替代标签。首次提交或失焦后提示校验，不在每次输入时抢焦点 |
| 错误定位 | 字段错误紧靠字段，设置aria-invalid与aria-describedby；提交失败聚焦可读错误摘要，提供字段定位；不清空合法输入 |
| 焦点与键盘 | 焦点有2px可见轮廓；Tab顺序跟随页面；三态使用同名radio组，方向键切换。对话框打开聚焦首个操作，关闭回到触发按钮 |
| 窗口与矩阵 | Chrome/Edge、1280×720以上为验收视口；窄窗口可单列/收起导航。宽矩阵只在自身滚动，不带动侧栏、不遮挡主要操作 |
| 文本与时间 | 纪要按纯文本展示，禁用v-html；日期输入明确“北京时间”，接口带时区，展示服务端时间；服务端决定截止和权限 |

三态含义固定为“有空＝可以参加、勉强＝需要协调、没空＝无法参加”；未知表示尚未提交，不是第四个可选答案。“排序首位”只说明顺序，不表示无冲突或全员可参加。

## 3. 字段和业务反馈

| 表单 | 正式实现规则与反馈 |
| --- | --- |
| 注册登录 | 用户名3～32字符，按12号规范化；邮箱最多254；密码8～128，拒绝纯空白，不trim。登录失败统一“账号或密码错误”，不透露账号是否存在 |
| 小组 | 名称1～100、说明0～10000；邀请码按接口校验。已加入不重复加入；满20人时明确提示；重置邀请码由负责人操作，说明旧码失效 |
| 排期草稿/发布 | 主题1～100、说明0～10000、地点0～200。草稿可暂存空参与者/时段；发布须至少1位组内参与者、1～15个有效且不重复时段，未来截止早于候选开始。发布后冻结结构 |
| 填写 | 各候选都选择后一次提交；截止前可覆盖本人。勾选数仅是本页输入，不计为已提交。保存失败保留全部选择；到期或关闭后只读，并保留结果入口 |
| 确认会议 | 只允许负责人从有效CLOSED首次确认；必到没空、必到未填或非首选须风险勾选及1～500字理由。确认成功进入原会议，不重复生成 |
| 议程与纪要 | 各0～10000字，负责人编辑、成员只读；保存时允许空文本。说明保存时间，加载失败不能用空文本覆盖服务端旧值 |
| 任务 | 标题1～100、说明0～10000、执行人必须组内、截止在未来；基础信息首版不提供编辑/删除。状态TODO/IN_PROGRESS/DONE可互换；完成默认从个人待办隐藏，重开后恢复 |

前端提示用于减少误操作，服务器校验决定是否成功。422将错误映射到已知字段；未知字段或无法定位时放入摘要。前端不直接展示框架异常、SQL、路径或原始错误堆栈。

## 4. 页面和保存状态

| 状态 | 展示与可操作行为 |
| --- | --- |
| 初始/就绪 | 页面数据成功加载后启用表单；有未保存更改时显示文字标记，离开或刷新需确认 |
| 加载中 | 显示“正在读取…”，容器aria-busy=true；保留结构，禁用依赖该数据的编辑和提交，不能显示为“暂无数据” |
| 空数据 | 只在成功读取且确实为空时显示；说明下一步。没有候选时等待发布，没有任务时提示负责人可创建，不伪造成功内容 |
| 提交中 | 按钮显示“正在保存…”，禁用重复提交；保留当前输入；短时间内重复点击不得再发写请求 |
| 读取失败 | 显示错误与手动重试入口；不覆盖已加载内容，不允许把占位空数据写回；非自动轮询 |
| 校验/保存失败 | role=alert错误摘要＋必要字段错误；保留草稿和原已保存状态，不先显示成功；可修改或手动重试 |
| 无权限/不存在 | 组外资源404统一“未找到可访问的资源”；组内403说明无权编辑，隐藏或禁用管理操作，不显示他组内容 |
| 保存成功 | 只在收到成功响应后显示role=status、服务端保存时间；更新相关详情。成功提示不抢焦点、不仅短暂闪过 |
| 网络超时/未确认 | 明确“尚未确认保存结果”，保留输入。先GET本人记录/原会议/原任务核对，再手动重试；不能凭超时断言未保存 |
| 会话过期 | 停止受保护操作并转登录；提示有未保存更改。仅保存安全的返回页面位置，不把答案或密码放入URL；重新登录后核对最新服务端数据再继续 |

受保护的草稿只在当前页面/内存保留，不在localStorage保存密码、Cookie、令牌或真实业务表单内容。重新登录更换账号时清除原账号草稿，同账号恢复也须重新检查对象权限。原型localStorage是模拟数据方案，不延续到正式版。

关闭收集、取消排期、重置邀请码需要说明影响的确认交互；确认会议显示时段、风险和人工理由。同slot确认重试复用原选择，任务创建重试复用同一个client_request_id；新任务才产生新标识。客户端10秒超时不代表服务端回滚。

## 5. 本轮完成与交接

T04已形成规范和可操作的状态示例。示例已验证状态切换、重复提交禁用、错误定位、未确认保存后的输入保留、会话过期后的只读提示、键盘三态选择与正文配色对比；它是开发参考，不代替T32桌面人工复核或5名真实用户易用性验收。

T06实现共用表单、错误摘要和请求状态；后续页面按第3节补全字段与边界，T30/T32对组件和完整流程验证。详细接口与错误code继续集中在12号，不在本文件复制另一份接口总纲。
