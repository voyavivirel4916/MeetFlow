# MeetFlow 开发约定

整理基线：B1｜2026-10-25。本文约定开发方式，适用于人工开发和Agent协作。第一版需求见[03](03-需求边界与MVP.md)，设计入口见[06](06-数据库API与页面设计.md)，验收见[07](07-验收标准与测试计划.md)。

## 1. 技术选择

| 部分 | 第一版选择 | 使用边界 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Vue Router、基础组件库 | 简单表单、矩阵与列表；状态管理和HTTP封装按需使用，不强制ECharts |
| 后端 | Python、FastAPI、SQLAlchemy、Pydantic | 模块化单体、单进程；依赖版本在脚手架阶段锁定并记录 |
| 数据库 | SQLite、显式迁移（计划使用Alembic） | 启用外键，独立测试库，启动不得自动清库 |
| 登录 | 服务端可撤销会话Cookie | 延续[现有系统设计](12-系统设计文档.md)，退出立即失效 |
| 测试 | Pytest、Vitest及人工验收 | 算法与边界测试、接口集成、关键前端组件 |
| 版本管理 | Git、Gitee、GitHub | 每次完成修改后提交，并同步同一提交到两边 |

依赖版本以实际安装清单和测试结果为准，不要求为了某个小版本重装系统。第一次选择、后续调整均记录原因和影响。

## 2. 代码组织

```text
Src/
  backend/app/     api、schemas、services、models、db、algorithms
  backend/tests/   单元与接口测试
  frontend/src/   views、components、api，其他目录按需建立
  frontend/tests/ 关键组件测试
  scripts/        验证、演示、启动和同步脚本
```

路由处理输入和响应，服务处理权限、业务规则及事务，SQLAlchemy负责持久化；推荐算法独立为无网络、无数据库依赖的纯函数。不要求为每张表增加repository类，复杂查询再提取存储访问模块。事务提交由业务服务统一负责。

## 3. 实施顺序

按[任务计划](08-分阶段开发与Agent提示词.md)完成：范围与原型 → 脚手架 → 账号小组 → 排期填写 → 推荐确认 → 纪要任务 → 集成验收。每阶段验证完成后再继续；每次变更保留可运行状态。

修改需求前先更新需求依据及变更记录；修改数据库同步迁移；修改接口同步前端类型和相关测试。不覆盖他人未提交的工作。用户明确决定优先于旧文档，发现跨文档冲突先核对最新决定及版本记录。

## 4. 质量底线

- 密码安全哈希，后端实施身份、小组与对象权限检查；配置、令牌、数据库文件不入库。
- 输入验证、事务原子性、唯一约束和截止边界在后端实现。
- 时间存储、接口格式、错误契约和会话安全遵循[系统设计](12-系统设计文档.md)，避免各模块自定格式。
- 页面提供加载、空数据、错误、无权限和成功反馈；保存失败不显示成功。
- 自动化测试与人工结果如实记录；文档测试通过不代表业务功能通过。
- 按根目录AGENTS要求完成相关验证与Git提交；双平台同步分别核对结果。

## 5. 运行与交付

第一版由本地同一服务提供前端构建文件和API，绑定127.0.0.1，SQLite持久化；开发服务器通过代理访问API。演示数据显式导入，备份采用停服后复制数据库。具体安装、迁移、启动、测试和恢复命令随着实现补充到[Src说明](../Src/README.md)。

公网发布属于后续课程交付，需另行验证HTTPS、Cookie、来源检查、访问控制和运行环境后再开放。当前本机HTTP配置不能直接用作公网配置。
