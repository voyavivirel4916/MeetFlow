## 数据和事务

分两次增量迁移，便于独立验证和保留第一版数据：

- `0006_poll_lifecycle`：polls增加deleted_at和archived_at（可空整数毫秒）；deleted_at非空只允许DRAFT/CLOSED/CANCELLED，archived_at非空只允许CONFIRMED，两者不能同时非空。增加(group_id, deleted_at, archived_at)索引。恢复清空deleted_at，不更改业务状态；归档不影响会议或任务查询。
- 后续任务迁移：tasks新增正整数version（默认1）及CANCELLED状态，保留现有完成时间约束。字段编辑和状态写入都携带expected_version，事务内校验后递增；旧版本409，不能靠updated_at毫秒相等识别版本。首版客户端在任务接口升级时一起更新，不留可绕过版本检查的旧写入口。
- 所有排期写操作使用现有BEGIN IMMEDIATE事务。删除与确认在取得写锁后检查相同排期，确认先成功则删除409，删除先成功则确认404。不物理删除参与者、时段或答案。
- 删除默认隐藏于普通详情、本人答案、矩阵、推荐和确认入口；恢复使用独立负责人入口，重复删除/恢复/归档不重复生成记录。
- 数据迁移在隔离旧库与故障注入下验证；回退使用已核对备份，禁止有损downgrade。只有正式页面接入且检查通过，才备份升级本机演示库。

## 排期接口

| 接口 | 权限与行为 |
| --- | --- |
| GET /groups/{g}/polls?view=current或history或trash | current默认仅非删除非归档；history仅已归档；trash只负责人；沿用分页与总数快照。旧客户端无view参数等同current |
| POST /polls/{p}/delete | EmptyIn，负责人；草稿、已关闭且无会议、已取消可删除，OPEN须先取消；已删除重复操作返回原记录 |
| POST /polls/{p}/restore | EmptyIn，负责人；清空删除标记，业务状态保持原样；非删除重复恢复返回当前记录 |
| POST /polls/{p}/archive或unarchive | EmptyIn，负责人；只允许CONFIRMED且未删除，重复同操作返回当前记录 |

PollOut增加deleted_at、archived_at（UTC字符串或null），原字段不变。普通成员与跨组访问回收站或恢复入口均不能读到已删除内容；组外404，组内无管理权限403。非法视图422；无效状态409。原分页排序不变。

## 任务接口后续契约

- TaskOut增加version；PATCH /tasks/{t}/status增加expected_version和CANCELLED。仅负责人可进入或离开CANCELLED；DONE不能直接取消，应先重开；恢复固定TODO。执行人仍只能操作正常三态。
- PATCH /tasks/{t}：负责人修改title、description、assignee_id、due_at，提供expected_version；字段允许部分提交但至少一项，不接受额外字段；只主动修改截止时要求未来。成员关系和版本均在锁内验证。
- 个人默认查询仅TODO、IN_PROGRESS，DONE/CANCELLED显式筛选；组任务默认全部。完成时间只为DONE设置，其他状态清空；归档不参与任务过滤。
- 工作台汇总和搜索在后续V2-12/14设计查询，不在本轮提前引入无验收依据的缓存或后台任务。
