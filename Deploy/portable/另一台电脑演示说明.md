# 在另一台电脑上独立演示 MeetFlow

适用：Windows 64位电脑，安装Python 3.11（64位，包含Python Launcher）。演示包包含已构建的网页与锁定的离线依赖，不需要Node.js；Python本体需要另行安装。其他系统未按这份入口验证。

## 三步启动

1. 将整个ZIP传给对方，完整解压到可写目录，例如桌面的MeetFlow-demo。不要在压缩包内双击，不要只复制某一个启动文件。
2. 双击“首次安装.cmd”，等待出现Ready。它会在新电脑上新建Python虚拟环境，使用包内依赖安装；不会连接公网下载依赖。
3. 双击“启动演示.cmd”，保留命令窗口，打开 http://localhost:8002/login 。虚构账号demo_owner，密码MeetFlowDemo2026!；demo_member1、demo_member2、demo_member3使用同一演示密码。

第一次启动会生成独立演示数据；同次展示再次启动保留填写与任务进度。11月6日展示日期预设在配置中，日期过去以后启动器会选新的有效展示日期，不冻结实际系统时钟。

## 这与访问原电脑的区别

复制演示包后，程序和数据库都在新电脑上。两台电脑各自运行、各自保存，不会自动同步；也不要求处于同一个Wi-Fi。包里没有原电脑的真实用户、数据库、会话、密码配置或练习进度。

如果希望两台电脑操作同一套数据，那是另一种“局域网共享”部署。当前程序本地模式限定127.0.0.1，生产模式还要求HTTPS与明确来源配置；不能只把监听地址改成0.0.0.0，或者把localhost改成一个IP，就认为部署和账户校验都解决了。本次采用独立运行，未开启局域网共享。

## 常见问题

- “py不是内部或外部命令”：安装Python 3.11并勾选Python Launcher，重新打开安装入口。不要把另一台电脑的.venv文件夹复制过来。
- 安装失败：先确认64位Python3.11，目录可写，ZIP已完整解压；保留错误文字。目录已有不完整.venv时不会自动清理，不要删除不明文件；可以把ZIP重新解压到新的空目录再安装。
- 浏览器拒绝连接：先运行启动入口，保持窗口。正常应看到Local demo地址；关闭启动窗口或关机后，下次需要重新启动。
- 端口占用：先打开现有8002地址；不要结束不认识的进程。也可在包根目录运行`Src\backend\.venv\Scripts\python.exe Src\scripts\run_showcase.py --port 8003`，再打开localhost:8003。
- 多账号切换：同一个浏览器普通标签页共享登录。可使用不同浏览器或独立浏览器配置，避免把切换账号误当成多人同时登录。
- 想保存进度：停止服务后妥善保留Src/backend/data目录。演示包不包含真实库，本次也不提供把原电脑真实库自动迁入的步骤。

## 推荐演示

工作台 → 小组 → “从这里开始：四人空闲填写” → 三个时段分别选勉强、有空、没空 → 保存并看推荐 → 结束收集并确认第二候选 → 写纪要和创建任务 → 我的任务手动完成。

演示账号是虚构样例，不是真人试用记录；公开的介绍网页也不等于完整应用已在线运行。
